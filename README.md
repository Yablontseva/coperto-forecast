# Forecasting Restaurant Guest Flow

Проект выполнен в рамках тестового задания на позицию **Junior Data Scientist**.

Цель проекта — прогнозирование количества гостей ресторана на следующие **7 дней** на основе исторических ежедневных данных.

---

## Результат

Для прогнозирования построен pipeline, включающий:

* анализ временного ряда;
* обработку пропущенных значений и закрытых дней;
* исследование сезонности и выбросов;
* генерацию календарных, лаговых и скользящих признаков;
* сезонный наивный baseline;
* модель `RandomForestRegressor`;
* временную валидацию;
* CLI для получения прогноза на 7 дней;
* автоматические тесты.

### Качество модели

Валидация проводилась на последних **42 днях** исторических данных.

| Model          |       MAE |       MAPE |
| -------------- | --------: | ---------: |
| Seasonal Naive |     17.10 |     27.23% |
| Random Forest  | **12.74** | **24.34%** |

Относительное снижение ошибки Random Forest:

* **MAE:** 25.5%
* **MAPE:** 10.6%

## Предобработка данных

В исходных данных отсутствуют календарные пропуски.

Часть пропущенных значений соответствует дням, когда ресторан был закрыт. Такие наблюдения были явно определены, а количество гостей для них установлено равным `0`.

Два наблюдения с пропущенным значением целевой переменной не заполнялись автоматически, поскольку их характеристики требуют отдельного рассмотрения.

Выбросы не удалялись автоматически по правилу IQR: экстремальные значения могут отражать реальные изменения посещаемости.

Для справки, по правилу IQR было обнаружено **24 статистических выброса**.

## Генерация признаков

Для модели используются следующие признаки:

| Признак           | Описание                           |
| ----------------- | ---------------------------------- |
| `day_of_week`     | день недели                        |
| `is_weekend`      | выходной день                      |
| `month`           | месяц                              |
| `week_of_year`    | номер недели                       |
| `is_holiday`      | федеральный праздничный день США   |
| `lag_1`           | количество гостей предыдущего дня  |
| `lag_7`           | количество гостей неделю назад     |
| `lag_14`          | количество гостей две недели назад |
| `rolling_mean_7`  | среднее за предыдущие 7 дней       |
| `rolling_mean_28` | среднее за предыдущие 28 дней      |

Лаги и скользящие статистики рассчитываются только по информации, доступной до прогнозируемой даты.

Это позволяет избежать утечки информации из будущего.

Генерация признаков вынесена в отдельный модуль:

```text
src/features.py
```

Одна и та же функция `make_features()` используется при обучении модели и при построении прогноза.

## Валидация

Поскольку задача является прогнозированием временного ряда, данные разделяются **по времени**, без случайного перемешивания.

Последние **42 дня** используются в качестве validation set.

```text
Train
2017-01-30 ───────────────── 2019-05-19

Validation
2019-05-20 ───────────────── 2019-06-30
```

Такой подход позволяет оценить качество модели на более позднем временном периоде, не используя информацию из будущего при обучении.

---

## Baseline

В качестве baseline используется сезонный наивный прогноз:

```text
prediction(t) = actual(t - 7)
```

То есть для каждого дня используется фактическое количество гостей в тот же день недели предыдущей недели.

Baseline позволяет проверить, даёт ли обучаемая модель дополнительное качество относительно простой недельной сезонности.

---

## Модель

Основная модель — `RandomForestRegressor`.

Параметры:

```text
n_estimators = 300
max_depth = 10
min_samples_leaf = 3
random_state = 42
n_jobs = -1
```

Модель реализована через `sklearn.pipeline.Pipeline`.

Фиксированный `random_state = 42` используется для воспроизводимости результатов.

Обученная модель сохраняется в:

```text
data/processed/restaurant_model.joblib
```

## Прогнозирование

Для построения прогноза используется CLI-скрипт:

```text
predict.py
```

### Запуск

```bash
python predict.py --date 2019-07-01 --restaurant 1
```

Скрипт строит прогноз на следующие **7 дней**.

Пример:

```text
Прогноз количества гостей:

      date  restaurant_id  predicted_guests
2019-07-01              1            173.70
2019-07-02              1            164.21
2019-07-03              1            168.96
2019-07-04              1            116.62
2019-07-05              1            174.40
2019-07-06              1            186.46
2019-07-07              1            181.38
```

Результат также сохраняется в:

```text
data/processed/forecast.csv
```

Прогноз строится рекурсивно: значение прогноза предыдущего дня используется для формирования признаков следующего дня.

## Обработка ошибок

CLI проверяет:

* наличие файла с данными;
* наличие сохранённой модели;
* наличие обязательных столбцов;
* существование указанного ресторана;
* корректность даты прогнозирования;
* отсутствие пропуска между последним историческим днём и датой начала прогноза.

При некорректных входных данных программа выдаёт понятное сообщение об ошибке.

## Итог

Проект реализует полный pipeline прогнозирования количества гостей ресторана:

```text
Исторические данные
        ↓
Предобработка
        ↓
EDA и анализ сезонности
        ↓
Генерация признаков
        ↓
Time-based validation
        ↓
Baseline + Random Forest
        ↓
Оценка MAE / MAPE
        ↓
Сохранение модели
        ↓
7-дневный прогноз через CLI
```

На валидационной выборке Random Forest показал:

**MAE = 12.74**

**MAPE = 24.34%**

против:

**MAE = 17.10**

**MAPE = 27.23%**

для Seasonal Naive baseline.

Таким образом, проект демонстрирует полный воспроизводимый цикл решения задачи временного прогнозирования — от анализа исходных данных до получения готового прогноза.
