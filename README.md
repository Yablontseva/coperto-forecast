\# Forecasting restaurant guest flow



Проект по прогнозированию количества гостей ресторана на следующие 7 дней.



\## Цель проекта



Цель проекта — построить модель прогнозирования количества гостей ресторана на основе исторических ежедневных данных.



В работе рассматриваются:



\- анализ временного ряда;

\- недельная сезонность;

\- календарные признаки;

\- лаговые признаки;

\- скользящие статистики;

\- базовый сезонный прогноз;

\- модель Random Forest;

\- временная валидация.

\## Предобработка данных



В ходе анализа были проверены:



\* пропущенные значения;

\* дубликаты дат;

\* календарные пропуски;

\* закрытые дни;

\* выбросы;

\* распределение целевой переменной.



В исходных данных отсутствуют календарные пропуски.



Часть пропусков в количестве гостей соответствует закрытым дням ресторана. Такие дни были явно выделены, и значение количества гостей установлено в `0`.



Два наблюдения с пропущенным значением целевой переменной не были автоматически заполнены, поскольку их характеристики требуют отдельного рассмотрения.



Выбросы не удалялись автоматически по правилу IQR, поскольку отдельные экстремальные значения могут отражать реальные изменения посещаемости.

Для анализа праздничных дней использовался календарь федеральных праздников США (`USFederalHolidayCalendar`).



Для открытых праздничных дней среднее количество гостей составило \*\*179.8\*\*, для обычных открытых дней — \*\*181.8\*\*.



Поэтому выраженного влияния федеральных праздников на количество гостей в рассматриваемом наборе данных не обнаружено. При этом признак `is\_holiday` сохранён для использования в модели.

Наибольшая корреляция наблюдается для лага в 7 дней, что дополнительно подтверждает наличие недельной сезонности.



\### Выбросы



Для выявления статистических выбросов использовалось правило межквартильного размаха (IQR).



\* Q1 = 171;

\* Q3 = 193.25;

\* IQR = 22.25;

\* нижняя граница = 137.625;

\* верхняя граница = 226.625.



По данному правилу было выявлено \*\*24 статистических выброса\*\*.



Выбросы не удалялись автоматически, поскольку часть экстремальных значений может соответствовать реальным изменениям посещаемости ресторана.



Закрытые дни были обработаны отдельно и не рассматривались как обычные наблюдения спроса.



\## Признаки



Для модели используются следующие признаки:



\* `day\_of\_week` — день недели;

\* `is\_weekend` — признак выходного дня;

\* `month` — месяц;

\* `week\_of\_year` — номер недели;

\* `is\_holiday` — федеральный праздничный день США;

\* `lag\_1` — количество гостей предыдущего дня;

\* `lag\_7` — количество гостей неделю назад;

\* `lag\_14` — количество гостей две недели назад;

\* `rolling\_mean\_7` — среднее количество гостей за предыдущие 7 дней;

\* `rolling\_mean\_28` — среднее количество гостей за предыдущие 28 дней.



При расчёте лагов и скользящих средних используется только информация, доступная до прогнозируемой даты. Это позволяет избежать утечки информации из будущего.



Генерация признаков вынесена в отдельный модуль `src/features.py`. Одна и та же функция генерации признаков используется при обучении модели и при построении прогноза.



\## Валидация



Для проверки качества модели используется временное разделение данных.



Последние \*\*42 дня\*\* используются в качестве валидационной выборки, что соответствует шести неделям.



Данные не перемешиваются, поскольку задача является прогнозированием временного ряда.



Обучающая выборка содержит наблюдения до начала валидационного периода, а валидационная выборка содержит последние 42 дня.



\### Базовая модель



В качестве базового метода используется сезонный наивный прогноз:



`prediction(t) = actual(t - 7)`



То есть прогноз на конкретный день строится на основе фактического количества гостей в тот же день недели предыдущей недели.



Такой подход позволяет сравнить обучаемую модель с простым методом, использующим обнаруженную недельную сезонность.



\## Результаты



На валидационной выборке получены следующие результаты:



| Модель         |   MAE |   MAPE |

| -------------- | ----: | -----: |

| Seasonal Naive | 17.10 | 27.23% |

| Random Forest  | 12.74 | 24.34% |



Для Random Forest снижение MAE относительно базового метода составляет около \*\*25.5%\*\*.



Снижение MAPE относительно базового метода составляет около \*\*10.6%\*\*.



Таким образом, на выбранном временном отрезке Random Forest показывает меньшие значения обеих использованных метрик по сравнению с сезонным наивным прогнозом.



\### Метрики



\*\*MAE (Mean Absolute Error)\*\* показывает среднюю абсолютную ошибку прогноза в количестве гостей.



\*\*MAPE (Mean Absolute Percentage Error)\*\* показывает среднюю абсолютную процентную ошибку.



При расчёте MAPE наблюдения с фактическим количеством гостей, равным нулю, не учитывались, поскольку деление на ноль не определено.



\## Модель



В качестве основной модели используется `RandomForestRegressor`.



Использованные параметры:



\* `n\_estimators = 300`;

\* `max\_depth = 10`;

\* `min\_samples\_leaf = 3`;

\* `random\_state = 42`;

\* `n\_jobs = -1`.



Модель находится внутри `sklearn.pipeline.Pipeline`.



Фиксированный `random\_state = 42` используется для воспроизводимости результатов.



Обученная модель сохраняется в файл:



`data/processed/restaurant\_model.joblib`

\## Прогнозирование



Для получения прогноза используется CLI-скрипт `predict.py`.



Пример запуска:



```bash

python predict.py --date 2019-07-01 --restaurant 1

```



Аргумент `--date` задаёт дату начала прогнозирования.



Аргумент `--restaurant` задаёт идентификатор ресторана.



Модель формирует прогноз на следующие \*\*7 дней\*\*.



Пример результата:



```text

Прогноз количества гостей:



&#x20;     date  restaurant\_id  predicted\_guests

2019-07-01              1            173.70

2019-07-02              1            164.21

2019-07-03              1            168.96

2019-07-04              1            116.62

2019-07-05              1            174.40

2019-07-06              1            186.46

2019-07-07              1            181.38

```



Результат также сохраняется в файл:



`data/processed/forecast.csv`



Прогноз строится рекурсивно: после получения прогноза на первый день это значение используется как историческое значение для формирования признаков следующих дней.



\## Обработка ошибок



Программа проверяет корректность входных данных.



Предусмотрены ошибки в следующих случаях:



\* файл с данными не найден;

\* файл модели не найден;

\* в датасете отсутствуют обязательные столбцы;

\* дата прогноза находится не после последней даты исторических данных;

Это позволяет избежать формирования прогноза на некорректных входных данных.

\## Итог



В рамках проекта проведён анализ ежедневного количества гостей ресторана, выполнена обработка пропущенных значений и закрытых дней, исследованы сезонность и выбросы.



Наиболее выраженной особенностью данных является недельная сезонность. На её основе были сформированы календарные, лаговые и скользящие признаки.



Для оценки модели использовалось временное разделение данных с последними 42 днями в качестве валидационной выборки.



В качестве базового метода использовался сезонный наивный прогноз с лагом 7 дней. Основной моделью выбран Random Forest.



На валидационной выборке Random Forest получил MAE \*\*12.74\*\* и MAPE \*\*24.34%\*\*, тогда как базовый метод получил MAE \*\*17.10\*\* и MAPE \*\*27.23%\*\*.



Таким образом, построенный программный pipeline позволяет выполнить полный цикл работы с задачей прогнозирования: от загрузки и анализа исторических данных до формирования и сохранения прогноза на следующие 7 дней.
